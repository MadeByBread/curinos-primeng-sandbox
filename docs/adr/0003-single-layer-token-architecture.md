# ADR-0003: Single-layer token architecture

## Status

Accepted. Supersedes ADR-0001 (bridge SCSS as source of truth for Transition token docs), which was removed in `9fa0074`.

## Context

Styling ran through two layers. Layer 1 was `--curinos-*`, generated from Figma. Layer 2 was `--primeng-*`, a hand-authored bridge in `tokens/primeng/_index.scss` keyed to PrimeNG 7 component anatomy, which `_overrides.scss` consumed.

The bridge was justified on the grounds that PrimeNG 7 has no native CSS-variable token system, so something had to describe its anatomy. Auditing its 84 tokens showed that is not what it was doing:

- **53 were pure one-hop pass-throughs.** `--primeng-dropdown-item-color: var(--curinos-color-foreground-2)` and 52 more like it. A rename with no added information.
- **4 were self-aliases**, one `--primeng-*` pointing at another.
- **27 were literals** with no Curinos source.

The literals were the real problem. They were nova-light's own values — `8.75px`, `12.25px`, `15.75px`, all rem arithmetic off a 14px root — sitting under Curinos-looking names. Meanwhile Curinos already shipped a `controls/sizing` scale (20/28/32/40/48/64px) that the bridge ignored entirely, and a `styles/control` type composite that `--primeng-button-lg-font-size: 15.75px` duplicated as a literal. For sizing, the bridge was not translating Curinos to PrimeNG; it was preserving PrimeNG's defaults while appearing not to.

The cost was also about to grow. Eight components needed 84 tokens. Covering the full Figma library, roughly 25 components, would have meant several hundred — most of them still pass-throughs.

Separately, the Figma library was simplified: the PrimeNG 22 "Prime \*" collections were deleted, leaving around 400 Curinos variables. Those remaining variables already include a semantic role tier — `background/1-4`, `foreground/1-3`, `border/1-3`, `semantic/{role}/{1,2,3}` — which is precisely what a well-designed Layer 2 would have introduced. The bridge was a second naming of a tier that already existed.

## Decision

1. **Delete Layer 2.** `tokens/primeng/_index.scss` is gone. `_overrides.scss` consumes `--curinos-*` directly.
2. **Controls are sized by height, not vertical padding.** `height: var(--curinos-dimensions-controls-sizing-lg)` with horizontal padding only, so Button, Inputs and Selects align at the same step for free. Textarea opts out; its height is not knowable up front.
3. **Values with no Curinos source stay literal, and stay collected.** They are SCSS variables at the top of `_overrides.scss` rather than scattered inline, so the gaps remain countable. Curinos has no spacing scale and no elevation scale; adding them to Figma was considered and deliberately deferred.
4. **Card layout modifiers move out.** The hero, section and compact treatments describe page scaffolding, not a component, and live in `styles/app/_layout.scss`. Figma has no Card page and that is treated as correct.
5. **Documentation is generated by reading the applied CSS.** `extract-component-catalogue.js` scans `_overrides.scss` for `var(--curinos-*)` usage inside `@component css:<key>` regions. This keeps ADR-0001's anti-drift property but inverts its direction: the tables describe what is applied, not what was declared.

## Consequences

- One less hop when reading a rule or debugging in DevTools. Curinos alias chains are already up to three deep; a fourth added nothing.
- Adding a component no longer requires authoring bridge tokens first. Write the CSS, add a marker comment, add a manifest entry.
- **Runtime themeability through `--primeng-*` is gone.** A consuming app can no longer restyle a component by setting one custom property; it would have to override the rule. Acceptable here — Curinos is the only theme, and dark mode is handled at Layer 1 where it belongs.
- **Component-anatomy naming is gone as self-documentation.** `--primeng-button-primary-background: var(--curinos-color-foreground-1)` explained that the primary button is deliberately an ink fill. Inline, `background: var(--curinos-color-foreground-1)` reads like a mistake. These few non-obvious mappings carry a comment instead.
- Renaming a Curinos token now means editing every call site rather than one bridge line. The Figma re-export that accompanied this change renamed four radii tokens and hit eight call sites — small, but it is the recurring cost.
- Sizing literals are no longer hidden. Anything still hardcoded is visible in one block at the top of the file, which is what should drive the decision about whether Curinos needs a spacing scale.
