The approach

There is no mapping layer. An earlier --primeng-* bridge renamed Curinos tokens for PrimeNG anatomy; most of it was a pass-through, and the rest was nova-light's own sizing wearing a Curinos name. Component CSS now reads --curinos-* directly. If a mapping is non-obvious — the primary button is an ink fill, not brand yellow — it gets a comment, not a second variable.

Markup stays vanilla PrimeNG. Wrappers and forked templates would make the stock comparison on the component catalogue meaningless: any difference you see there has to be styling.

Documentation is generated backwards. The catalogue does not record what a component is supposed to use. It reads the CSS that is applied, so a token that stops being spent disappears from the table. See Curinos Tokens for the export format.

An example: Button

Figma draws several button sizes and a row of semantic fills. In code that is one .ui-button, a size class, and a severity class. Height comes from controls/sizing. The default fill is foreground-1; Success spends semantic/success/1.
